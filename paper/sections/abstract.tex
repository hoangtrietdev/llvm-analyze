The end of Dennard scaling has made thread-level parallelism the main source of performance growth, yet converting legacy serial loops into correct OpenMP code is still expensive expert work. Sound static analyzers never introduce a data race but leave many parallel loops sequential; large language models (LLMs) recognise algorithmic intent that a compiler cannot prove, but they offer no correctness guarantee. We present \SystemName{}, a six-phase ``check-then-ask'' framework for loop-level parallelization. An LLVM~21 analysis (HF-Static) classifies every loop as \textsc{Parallel}, \textsc{Serial} or \textsc{Unknown}; proven decisions are final, a static veto and a call-site alias guard block every loop with a known dependence, and only the remaining undecided loops are sent to an LLM together with the compiler's reasons, behind a confidence threshold $\tau$ calibrated on held-out data. To avoid judging a compiler against its own output, every ground-truth label is validated by execution: on HF-LoopBench (\nBenchLoops{} target loops from \nBenchBases{} kernels in \nBenchDomains{} domains) all \nOracleVerified{} parallel labels reproduce the serial result under 12 OpenMP thread/schedule configurations, and all \nOracleManifested{} canonical serial labels produce wrong results under naive parallelization. HF-Static is precise (\fsStaticPrec{}) but proves only \fsStaticRec{} of the parallel loops (GCC \fsGccRec{}, Polly \fsPollyRec{}). Used alone, GPT-OSS-120B and GPT-OSS-20B reach F1-scores of \evAIOneTwentyFone{} and \evAITwentyFone{} on a \nEvalLoops{}-loop evaluation set but declare \evAIOneTwentyFP{} and \evAITwentyFP{} serial loops parallel, mostly by ignoring how a function is called. The complete hybrid with GPT-OSS-20B reaches F1 \evHCTwentyFone{} with zero unsafe directives on that set and \fhTwentyFone{} with \fhTwentyFP{} unsafe directives on all \nBenchLoops{} loops, while querying the model for only \projFracTwenty{} of the loops at \projSaveTwenty{} lower token cost than LLM-only classification. On a loop-structure extension written after the study was frozen (\xLoops{} loops: inner-versus-outer targets, triangular, strided, decrementing, pointer-walking and conditional loops), the frozen pipeline reaches F1 \xHTwentyFone{} with \xHTwentyFP{} unsafe directives, and the extension exposed a soundness bug in the static analysis that we report and fix. We further show that similarity-based answer caching introduces unsafe answers, quantify token cost under real API limits, and release all data, request/response logs and scripts.
